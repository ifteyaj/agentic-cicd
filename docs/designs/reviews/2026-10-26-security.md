## Findings

| ID | Severity | Finding | Resolution |
| --- | --- | --- | --- |
| WH-01 | Critical | Empty secret yields `""`, not `None`, so HMAC uses an empty key and anyone can forge. | Accepted. Absent/empty/whitespace/`change-me` → 503 before body read; `SecretStr`. |
| WH-02 | High | Unauthenticated body-size DoS; route may read unbounded body before checking secret/header. | Accepted. Secret/header checks before read; 1 MiB streaming cap; 413. |
| WH-03 | High | Delivery ID is outside the HMAC; captured request replayed with a new ID creates unlimited runs. | Accepted as documented risk. TLS + secret + bounded store; content dedupe deferred. |
| WH-04 | High | Process-local dedupe fails with multiple workers; sequential test proves no atomicity. | Accepted. Single-process constraint documented; one lock; concurrency test. |
| WH-05 | Medium | Algorithm-confusion test uses a SHA-256 digest under `sha1=`, so it cannot detect the flaw. | Accepted. Test uses a valid SHA-1 HMAC; verifier hard-codes SHA-256. |
| WH-06 | Medium | Unsigned delivery ID allows log injection and unbounded dict keys. | Accepted. `^[A-Za-z0-9-]{1,128}$`; structured logging. |
| WH-07 | Medium | Malformed/non-ASCII signatures can raise 500. | Accepted. Strict regex; catch-all → 401. |
| WH-08 | Medium | `html_url`, arbitrary hosts, credentials in URL, short/zero SHA accepted. | Accepted. `clone_url` only, HTTPS GitHub host, no userinfo, 40/64 non-zero SHA. |
| WH-09 | Medium | Acceptance claims exceed test plan; no no-run assertions; verify-before-parse untested. | Accepted. §15 expanded; every negative test asserts zero runs. |
| WH-10 | Low | Log/secret hygiene unspecified. | Accepted. `SecretStr`; no headers/body/secret in logs. |

## Verdict

FIX SPEC FIRST at revision 1. Revision 2 addresses WH-01, WH-02, WH-04, WH-05,
and WH-09, and records WH-03 as an accepted, bounded risk.
